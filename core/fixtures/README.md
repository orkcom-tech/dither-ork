# Reference images

Generated. **Do not edit these by hand and do not re-encode them with anything
else** — they are compared byte for byte, and a well-meaning `pngcrush` run
would silently invalidate the whole set.

```
source/<fixture>.png                     the generated test images themselves
golden/<fixture>/<palette>/<kernel>.png  one reference per combination
```

## What is being tested

`core/crates/dither-core/tests/golden.rs` renders every fixture in
`dither_core::fixture::FIXTURES` through every kernel in
`dither_core::diffusion::KERNELS` against each of its two palettes, and compares
the result to the file above. Thirteen of the fourteen kernels are a coefficient
table transcribed from a published paper, and a transposed digit in one of them
still produces a picture — a stored reference is the only thing that catches it.
See the module documentation in `golden.rs` for the comparison rules and why the
tolerance is zero.

The **inputs are not stored**. They are generated by `dither_core::fixture`,
which is code a reviewer can read; `source/` holds a rendering of each one so
that a change to a generator shows up as one legible image diff instead of 140
unexplained ones. Nothing reads `source/` back as input.

## Regenerating

```bash
docker compose run --rm --entrypoint bash wasm -c \
  'cd /app/core && DITHER_ORK_BLESS=1 cargo test -p dither-core --test golden'
```

This **replaces every file below this directory** with whatever the current
build produces, and says so on stderr while it does it. Re-run without the
variable afterwards to confirm the new set is stable, and look at the image diff
before committing — that diff is the entire point of the exercise.

`DITHER_ORK_BLESS` must never be set in CI. With it set the harness writes
instead of checking, and every run passes.
